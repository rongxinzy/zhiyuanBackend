# ZhiYuan Model Pool infrastructure

This directory owns the Cloudflare resources for the ZhiYuan Model Pool business layer. The Worker validates desktop access tokens through the community authentication Worker's private `AuthService` Service Binding; no signing key or public introspection endpoint is duplicated here.

## Environments

| Environment | Worker | D1 | KV |
| --- | --- | --- | --- |
| Production | `zhiyuan-model-pool` | `zhiyuan-model-pool` | `zhiyuan-model-pool-config` |
| Staging | `zhiyuan-model-pool-staging` | `zhiyuan-model-pool-staging` | `zhiyuan-model-pool-config-staging` |

The `UserQuota` SQLite Durable Object namespace is provisioned by the first deployment of each Worker environment.
Production is exposed only through `https://model.rongxzyai.com`; the `workers.dev` route remains enabled only for staging.

## Commands

Run from the `zhiyuanBackend` repository root:

```bash
npm run types:model-pool
npm run check:model-pool
npm run smoke:model-pool:staging
npm run migrate:model-pool:staging
npm run deploy:model-pool:staging
npm run migrate:model-pool
npm run deploy:model-pool
```

The deployed slice exposes `GET /health`, `GET /v1/models`, and `POST /v1/chat/completions`. Model endpoints require a current signed ZhiYuan desktop token. Signed-in users are provisioned into the `FREE` plan with 100 requests per day, 100,000 tokens per day, and 3,000,000 tokens per month. Signed-out desktop installations receive a short-lived guest token and are provisioned into the `GUEST` plan with 100 requests per day, 20,000 tokens per day, and 100,000 tokens per month. Both plans receive a `zhiyuan-free` entitlement. D1 is authoritative for identity status, plan limits, entitlements, logical-model availability, route metadata, and identity-level daily usage. KV holds the hot runtime route configuration. Request and token admission is serialized by a `UserQuota` instance named from the authenticated identity ID.

Guest identity is based on a random installation UUID generated by the desktop app, not a hardware fingerprint. Clearing the app's local data creates a new guest identity; issuance rate limiting provides best-effort abuse control, while account login remains the durable identity boundary for larger quotas.

Staging additionally accepts `MODEL_POOL_TEST_TOKEN` for automated smoke tests. Production code never accepts that static token, even if the secret remains configured during a rollout. The `UPSTREAM_API_KEY` secret is used only by the short-lived `direct-test` route mode.

The cloud test route uses `mode: workers-ai-test` and calls Workers AI through the `default` AI Gateway. It validates authentication, logical-model rewriting, quota, gateway observability, streaming, and tool calls without exposing an external provider key.

The production route mode is `ai-gateway`. It invokes a named Cloudflare Dynamic Route through the Workers AI binding and the Gateway `compat/chat/completions` endpoint. Provider credentials, retries, timeouts, budgets, and the BYOK provider fallback order belong to the Dynamic Route. If every Dynamic Route provider fails, the Worker makes one final direct Workers AI binding call because Workers AI model nodes currently lose the OpenAI-compatible request body on this Dynamic Route path. A production KV value has this shape:

```json
{
  "enabled": true,
  "mode": "ai-gateway",
  "protocol": "openai",
  "gatewayId": "default",
  "routeName": "free-agent-openai"
}
```

The `mode: direct-test` route remains available only for short-lived provider compatibility diagnostics. Restore the environment's normal route immediately after a diagnostic; never expose `direct-test` as the public model service.

## Dynamic Route provisioning

The checked-in route graph is `cloudflare/free-agent-openai.route.json`. Its current BYOK fallback order is Groq then OpenRouter; the Worker provides the final Workers AI fallback. Agnes is intentionally excluded while its origin rejects Cloudflare egress with HTTP 1015.

Protocol admission results and the current Anthropic activation boundary are recorded in `PROVIDER_COMPATIBILITY.md`.

Cloudflare management calls for this graph require a dedicated API token. Give the token only these account permissions:

- AI Gateway: Read and Edit
- Secrets Store: Read and Edit

Store the token outside the repository. The ordinary Wrangler OAuth token can deploy Workers and manage Secrets Store values, but it cannot create or deploy AI Gateway Dynamic Routes.

BYOK secret names must follow Cloudflare's `{gateway_id}_{provider_slug}_{alias}` convention. For gateway `default`, this project uses `default_groq_default` and `default_openrouter_default`, each scoped to `ai_gateway`. After the provider configurations and route version are deployed, run the compatibility probes against the Dynamic Route before changing KV from `workers-ai-test` to `ai-gateway`.

D1 marks `zhiyuan-free` active, records `free-agent-openai` as its OpenAI route, and seeds the `FREE` plan with request and token limits. KV contains the runtime route configuration. Disabling a user, entitlement, logical model, or route mapping in D1 takes effect on the next request. Removing an existing user's entitlement does not cause it to be automatically recreated; automatic entitlement provisioning applies only when the user is first created.

For a staging operator smoke test, store the bearer token in `workers/model-pool/.test-token` with file mode `0600`. The path is ignored by Git. Rotate the staging `MODEL_POOL_TEST_TOKEN` secret whenever this local token is replaced. Production smoke tests use a real desktop access token.

`npm run smoke:model-pool:staging` verifies health, unsigned-request rejection, guest token issuance, guest model access and inference, the authenticated logical-model list, non-streaming inference, required tool calling, streaming termination, logical-model rewriting, and token usage. Override the endpoint, account endpoint, or token path with `-- --base-url <url> --auth-base-url <url> --token-file <path>`. Add `--guest-only` when validating production without a signed-in user's token file.

## AI Gateway boundary

Wrangler does not currently expose AI Gateway or Dynamic Route management commands. Create the Gateway, stored provider credentials, and Dynamic Routes through the Cloudflare dashboard or through the REST API with a dedicated Cloudflare API token that has `AI Gateway - Read` and `AI Gateway - Edit`. Wrangler OAuth tokens are not used as long-lived project credentials.

Cloudflare Dynamic Routes currently run through the OpenAI-compatible `/compat/chat/completions` endpoint. The Worker passes `dynamic/<routeName>` as the upstream model and does not forward Cloudflare's provider/model response headers to clients. Do not mark the Anthropic route mapping active until Cloudflare supports Dynamic Routes on the Anthropic-native endpoint or the architecture explicitly chooses a protocol adapter.
